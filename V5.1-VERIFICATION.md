# MEME.RADAR V5.1 verification

## Prerequisites

- Node.js 20+
- The bot's environment variables configured from the existing deployment
- `MEMERADAR_SYNC_SECRET` set to the same secret value as the Worker `BOT_SYNC_SECRET`
- Telegram `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` for command checks

## Quick checks

```sh
npm run check
npm test
npm run dry-run
```

`npm run dry-run` fetches the live discovery feed and performs an authenticated Worker/D1 read. It does **not** open or close positions, write the portfolio file, or POST to D1.

## Telegram check

```sh
node meme-radar-bot.mjs --telegram-test
```

The bot sends one test message to the configured chat. In persistent mode, supported commands are `/status`, `/positions`, `/pause`, `/resume`, and `/close SYMBOL`. Commands from any chat other than the exact configured `TELEGRAM_CHAT_ID` are ignored.

## D1 versioned sync check

```sh
node meme-radar-bot.mjs --sync-check
curl -s -H "Authorization: Bearer $MEMERADAR_SYNC_SECRET" \
  https://memeradar-state-api.varmaabhi47.workers.dev/state \
  | jq '{version, updated_at}'
```

`--sync-check` reads the current D1 version, then writes the current bot portfolio with that expected version. It does not run discovery or execute paper trades; it increments the D1 version and `updated_at`. A stale/concurrent write returns HTTP 409 and is not applied.

## Persistent runner

```sh
RUN_MODE=persistent node meme-radar-bot.mjs
```

This runs the position monitor at approximately 12-second intervals while positions are open, discovery approximately every 180 seconds, research snapshots every 5 minutes, and Telegram polling every 5 seconds. Keep it under a process manager or persistent Node worker for 24/7 operation. The default mode remains one scheduled scan per process.

## Dashboard and API

- Dashboard reads `/public-state` only; it never uses browser-local portfolio state.
- `GET /state` and `POST /state` require `Authorization: Bearer <secret>`.
- `POST /state` requires the expected integer `version`; stale writes return 409.
- `/public-state` is a sanitized read-only dashboard view.
- The system remains paper-only; no wallet signing or swap execution is enabled.
